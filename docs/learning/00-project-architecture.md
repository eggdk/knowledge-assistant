## 我们在做什么

管理员将资料导入知识库。访客点开网站角落的问答按钮，系统找出相关原文，请千问据此组织答案，逐段显示文字并提供可展开的引用。管理员可以根据资料不足的问题和反馈继续补充知识。

课程还要求把插件实际集成进 Agent Insight。当前独立演示网页的问答流程已跑通，实际宿主集成仍待完成。

管理网页和聊天插件共享后端。默认前端端口为 5173，后端为 8000；Vite 将网页的 /api 请求转发到后端。独立联调曾使用 5175 和 8002，它们属于临时测试服务。

## 资料进入系统时发生什么

以上传一份巡检手册.docx 为例：

1. 网页把文件字节和相对路径发给上传接口。CLI 从用户指定目录读取文件。
2. 两种入口共用 import_document，解析器提取 Word 正文和表格中的文字。
3. 后端计算 SHA-256 文件指纹。新路径创建 v1，相同路径且内容不变返回 unchanged，内容变化返回 updated 并增加版本。
4. 文字切成短块，每块记录文件、版本、标题、行号和字符位置。
5. 原件、提取文字、版本和文本块存进本机 SQLite，文件开始参与检索。

坏文件解析失败时，之前可用的版本继续保留。同批文件可以部分成功、部分失败，页面分别展示结果。

源文件变化后，需要主动重新导入或上传来同步。当前尚未实现自动监控本地目录。

## 提问到回答的完整流程

~~~mermaid
sequenceDiagram
    participant U as 访客
    participant W as 插件
    participant A as 后端
    participant D as SQLite
    participant Q as 千问
    U->>W: 巡检周期是多久？
    W->>A: 问题及最近三条用户问题
    A->>D: 读取有效版本文本块
    D-->>A: 候选原文
    A->>Q: 当前问题、需要的上下文及片段
    Q-->>A: 增量生成结果
    A-->>W: delta，追加生成中的文字
    A->>A: 解析完整结果并核验引用编号
    A->>D: 保存最终回答与引用快照
    A-->>W: final，答案、引用和 answer_id
    W-->>U: 显示完整答案与可展开引用
~~~

没有检索命中时，后端直接返回资料不足；模型也可以根据候选原文判断资料不足。有命中但缺少密钥时，后端返回 503，插件回退到相关原文并标注“尚未生成答案”。

delta 是生成中的文字。最终结果解析和引用编号校验通过后才发送 final。生成中断或连接在 final 前关闭时，插件清掉半截预览并提示重试。

引用校验确认模型使用的编号属于本次检索结果。回答是否正确、每句话是否真正受到证据支持，仍需正式评测与人工复核。

## 各模块负责什么

### 管理网页和悬浮插件

前端位于 apps/web，使用 React、TypeScript 和 Vite。

- files.html 是管理入口，支持建库、切换库、选择文件或目录、上传、筛选、删除、查看版本和检索状态。
- index.html 是宿主演示页，通过 public/embed.js 加载悬浮按钮与 iframe。
- widget.html 加载 src/main.tsx 中的聊天界面。
- 宿主通过 data-kb-id 指定知识库，演示页支持网址参数 kbId。
- 插件发送最近三条用户问题，收起后重新打开保留本页会话，“新对话”清空会话。

后端已有文档提取文本、原件下载、问答对和反馈接口，相关页面尚待接入。目前文件详情弹窗主要显示列表里已有的元信息。

### HTTP 服务与接口

apps/api/app/main.py 创建 FastAPI 应用，api_routes.py 定义路径、参数和响应。Uvicorn 启动应用，接收浏览器 HTTP 请求。

现有接口包括建库、列库、文件列表、上传、删除、文档详情、版本原件下载、问答对创建编辑、原文检索、完整答案、流式答案、反馈提交和回答记录查询。

/health 用来检查服务响应，/docs 是自动生成的接口操作页。上传时应选择文件，让浏览器发送内容。具体路径和请求示例见[知识库接口](../api/knowledge-base-v1.md)、[答案接口](../api/answer-generation-v1.md)及[新增接口交接](../2026-11-18-backend-handoff.md)。

### 本地命令行

cli.py 提供建库、列库、目录导入、列文档、查看文本块、重建块和搜索。CLI 与网页共用解析、存储及分块逻辑。测试已验证新格式经两种入口导入后都能被检索。

### 导入与解析

directory_scan.py 查找指定目录中的受支持文件，import_service.py 组织批量导入，text_parser.py 按格式提取文字。

- MD/TXT 读取 UTF-8，接受 BOM，统一换行。
- DOCX 提取正文段落和表格。
- XLSX 读取工作表单元格，并保留工作表名。公式读取文件里已有的缓存结果。
- PDF 提取已有文字，加入原始页码标记。纯扫描件须先做 OCR，加密文件须先解除保护。
- 旧版 DOC/XLS 需先转换成 DOCX/XLSX。

HTTP 上传每批最多 20 个文件，每文件最多 5 MiB。引用行号属于提取后的文本。

### 数据库、原件和版本

knowledge_store.py 管理知识库、文档、原件、版本、文本块和删除状态。answer_records.py 保存最终问题、上下文、答案、引用快照及最新反馈。

默认数据库为 storage/knowledge.sqlite3，可以用环境变量 KNOWLEDGE_ASSISTANT_DB 指定独立数据库。运行数据和密钥在本机保存，Git 会忽略 storage 目录。

删除后，文档退出活动列表和检索，历史及原件仍保留。同路径重新上传可恢复。CLI 导入时如果选择跳过原件，仍可读取提取文字，下载该版本原件会返回 404。

### 分块与检索

chunking.py 使用 mdtxt-v2 策略。文本块目标上限 600 字符，相邻块目标重叠 80 字符，尽量在标题、段落和句子附近切分，并记录原文位置。

retrieval.py 检索未删除文档的当前版本，使用中文双字和 jieba 分词两路关键词打分、合并排序。关键词检索已有优化和评测，向量语义检索尚未实现。

searchable 为 true 表示当前版本有可参与检索的文本块。检索分数用于排序，不能直接当作答案正确率。

### 模型、引用和多轮

answer_generation.py 通过百炼兼容接口调用 qwen3.7-plus。密钥留在后端，模型收到当前问题、需要的历史问题与少量检索片段。

后端按显式指代等规则理解“它”“刚才”等简单追问，最多接收三条先前用户问题。简单连续追问已经联调，复杂长对话和跨主题指代仍需评测。

前端能展开引用，看到文件、行号和原文。模型生成答案会消耗百炼额度，文档管理和原文检索无需模型调用。

### 直接录入问答对与反馈

人工录入的一问一答保存为 qa/随机编号.txt，沿用文档的版本、检索、引用和删除流程。编辑时已被删除的条目返回 404。

普通答案及流式 final 都带 answer_id。反馈带回这个编号，记录“有帮助／没帮助”和备注。资料不足与负面反馈可以通过 needs_review 筛选列出。当前每次回答保留一份最新反馈，尚未区分多用户投票。

这些后端已完成测试，问答对录入页面、回答下方反馈按钮和待补充问题列表仍待接入。

### 测试和评测

apps/api/tests 验证版本、接口、隔离、检索和流式失败等程序行为。合并后的完整后端结果为 109 项通过、1 项跳过。前端类型检查、构建、嵌入检查和文件管理回归检查通过。

evals/demo 是虚构演示集，evals/agent_insight 是固定的公开文档及团队题目。旧的 Top-1/Top-5 结果保留在相应学习笔记中，应按当时版本理解。下一轮需要独立问题，检查检索、最终答案、引用支持程度和拒答。

## 从哪里运行

先在仓库根目录安装后端依赖：

~~~powershell
& .\.venv\Scripts\python.exe -m pip install -r apps/api/requirements.txt
~~~

终端一从仓库根目录进入后端目录并启动：

~~~powershell
Set-Location apps/api
& ..\..\.venv\Scripts\python.exe -m app.dev_server
~~~

按终端提示选择地域并输入 API Key。只验证文档管理和原文检索时可加 --without-model。本机另有 Git 忽略的便捷密钥配置，属于个人运行环境；同学拉取代码后需要配置自己的运行环境。

终端二从仓库根目录进入前端目录：

~~~powershell
Set-Location apps/web
npm.cmd install
npm.cmd run dev
~~~

打开前端输出的地址，从文件管理页建库、上传文件，再点击“前往问答演示”。两个终端需要同时运行。
