# 第 4 课：为什么要把资料切成小段

假设一本手册有 100 页，用户只问“登录失败怎么办”。以后检索时不应该把整本手册塞给模型，而是先找到相关的几段文字。这样的“一小段”就是 **chunk（文本块）**。本轮只完成切块和保存，**尚未实现搜索或问答**。

## 你可以看到什么

先按第 2 课创建知识库并导入 `examples/sample_docs`。然后在 `apps/api` 目录运行：

```powershell
& ..\..\.venv\Scripts\python.exe -m app.cli chunks list --kb 你的kb编号
```

输出会列出文件、版本号、块序号、原文行号、字符数和所属标题，不打印完整正文。示例资料较短，通常一篇只有一块；自动化测试另用长文验证多块与重叠。

如果你之前已经导入过同一份资料，用现在的程序**再导入一次**即可：文件内容没变，版本号不会增加，但会补上这轮新增的分块记录。

## 代码怎么走

1. `text_parser.py` 先把 MD/TXT 解码并统一换行；这一步让不同系统的行号规则一致。
2. `chunking.py` 先识别 Markdown 标题（代码围栏里的 `#` 不算标题），再尽量在自然段、句号或换行处切分。起始参数是每块最多 600 字符、相邻长块约重叠 80 字符。
3. 每块保存原文的字符起止位置、行号范围和标题路径。例如 `安装 / Windows`、`L12-L18`。块的正文必须等于原文对应位置的原样切片，而不是模型“改写”的内容。
4. `knowledge_store.py` 把块与知识库、文档 ID、版本号和分块策略版本一起存入 SQLite。查询时只拿**当前文档版本**对应的块；旧版本的块保留供以后追溯。

“字符位置”是 Python 字符串位置，不是 UTF-8 字节位置；不能直接拿它去裁剪原始二进制文件。保存原件和解析后的正文，就是为以后校对引用准备的。

## 需要特别理解的两个边界

- **切块不等于检索。** 我们现在能得到若干小段，还不知道用户的问题应该匹配哪几段。因此网页接口仍返回 `searchable: false`。
- **字符数不等于模型 token 数。** 600 字符只是先跑通课程样例的实验值。以后选定向量模型/大模型后，需要按它们的真实输入预算评估，不应直接宣称“600 字符最优”。

测试检查长段不超过上限、相邻块重叠、Markdown 标题和代码围栏、每块能定位回原文、两份知识库不会串块、更新只读取当前版本，以及切块保存失败时旧版本仍在。接下来才适合实现一个不接大模型的检索基线，先证明“问题能找对资料”。
