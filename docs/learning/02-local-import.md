# 第 2 课：本地文件是怎样进入知识库的

这是 A 岗后端的第一个可用数据流程，尚未包含检索、大模型问答、网页上传或 Agent Insight 插件。

## 先用一句话理解

你选定一个文件夹，程序只找其中的 `.md`、`.txt` 文件，读取正文并存进 SQLite。下次再导入时，它会通过文件内容的 SHA-256 值判断是“没有变化”还是“生成新版本”。

## 你可以自己运行一遍

在仓库根目录打开 PowerShell，然后运行：

```powershell
Set-Location apps/api
& ..\..\.venv\Scripts\python.exe -m app.cli kb create --name "课程演示"
& ..\..\.venv\Scripts\python.exe -m app.cli kb list
```

复制输出的 `kb_...` 编号，用它替换下面的 `你的编号`：

```powershell
& ..\..\.venv\Scripts\python.exe -m app.cli import --kb 你的编号 --dir ..\..\examples\sample_docs
& ..\..\.venv\Scripts\python.exe -m app.cli docs list --kb 你的编号
```

再执行一次相同的导入命令，原本的 `CREATED` 应变成 `UNCHANGED`。如果想亲眼看见 `UPDATED ... v2`，请先把示例文件夹复制成自己的临时测试文件夹，再修改其中一份文件并导入；不要为了测试而修改正式课程资料。

团队已决定默认保留原文件副本，因此命令不写 `--originals` 也会在数据库中保存原始字节。特殊情况下可明确写 `--originals skip`，这时仅保存解析后的正文和文件路径。两者都可以用于后续检索；保留原件更利于精确追溯，但数据库会更大。

## 代码怎么串起来

1. `app/cli.py` 接收你输入的命令与知识库编号。
2. `app/directory_scan.py` 只扫描你指定的文件夹，记录相对路径，并拒绝符号链接；不会偷偷扫描整台电脑。
3. `app/import_service.py` 逐文件调用公共入库接口。一个文件失败会给出原因，不会挡住其他文件。
4. `app/text_parser.py` 将 UTF-8（包括 BOM）转换为统一换行的正文；乱码、空文件和不支持的格式明确报错。
5. `app/knowledge_store.py` 先查知识库和已有文档，再比较文件哈希。在同一个数据库事务里写入新版本并切换当前版本。解析失败时旧版本仍可用。

未来网页上传也应该调用第 4、5 步的公共逻辑，而不是重新写一套“网页专用解析器”。

## 几个必须分清的概念

- **知识库**：资料的分组；两份知识库即使有同名文件，也不应该串资料。
- **相对路径**：例如 `manual/intro.md`；目前是该知识库内识别一份文档的键。把文件改名或移动路径，会被视作新文档，旧文档不会自动删除。
- **版本号**：同一路径的内容变动后从 `v1` 变为 `v2`。重复导入相同字节不增加版本。
- **SHA-256**：文件内容的“指纹”，用于发现变化；不是加密文件，也不是查重所有语义相同的文字。
- **解析正文**：以后供分块和搜索使用；现在只是存储，还不能据此回答问题。
- **原始字节**：默认保存的原件副本。即使特殊情况下选择 `skip`，仍会存解析后的正文，因为问答需要它。

## 怎样验证

在 `apps/api` 目录运行：

```powershell
& ..\..\.venv\Scripts\python.exe -m pytest -q
```

测试覆盖中文与 BOM、错误编码、空文件、目录边界、创建与更新版本、不变文件跳过、两库隔离、坏更新不覆盖旧版本、部分导入不误删、命令行基本流程。符号链接测试在部分 Windows 账户上可能跳过，因为系统不允许普通账户创建链接。

## 当前边界与下一步

这一阶段不处理 Word/Excel/PDF，不做分块或检索，不会调用大模型 API，也没有网页上传和真正的 Agent Insight 集成。下一步适合加“已导入文档的查看/删除接口”，让 B 岗网页能接上；之后再做分块和检索。
