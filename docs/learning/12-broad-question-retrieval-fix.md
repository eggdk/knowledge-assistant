# 第 12 课：让“如何管理实验？”找回正确资料

更新于 2026-11-10。这次改的是“找资料”，没有更换千问，也没有增加付费服务。

## 原来的问题出在哪

检索会把问题里的词逐个拿去找原文，再加分排序。“Agent Insight 如何管理实验？”里，产品词、“如何”和“管理”也会得分，导致“如何关联原 Trace”等无关段落挤掉了真正的实验入口说明。模型拿不到正确原文，就容易返回资料不足。

## 现在怎样处理

在 `apps/api/app/retrieval.py` 中，先准备一份**只用于检索打分**的问题副本，去掉少量通用问法，例如“如何管理”“怎么使用”“请问”。“删除”“导出”、否定词、数字和错误码等具体要求保留；如果去完什么也不剩，就使用原问题。用户原话仍然交给千问，原文也完整保留。

然后照原来的双路关键词方法打分。如果问题完整提到了文档的主题标题，例如文档的顶层标题“实验”，就把该文档中有匹配的片段分数乘 2。它只是帮助正确主题往前排，并不会禁止返回其他文档。代码没有写死“实验”“Agent Insight”或某份文档路径，其他知识库也使用同一套规则。

可以沿着这四步读代码：`_retrieval_query()` 准备打分用的问题 → `tokenize()` 与 `_search_words()` 提取词 → `_bm25_scores()` 打分 → `_matches_document_title()` 判断完整主题标题是否匹配。原文的文件名、版本、行号和内容照常随结果返回。

## 实际改善了多少

- “Agent Insight 如何管理实验？”：正确入口原文从前五之外来到 **第 2**。
- “如何管理实验？”：从前五之外来到 **第 4**。
- “实验列表和创建实验”：保持 **第 1**。
- 原有 Agent Insight 18 道有答案题：Top-1 仍为 **12/18**，Top-5 仍为 **17/18**，每道题的答案排名均未改变。
- 原有虚构演示集：Top-1 仍为 **10/12**，Top-5 仍为 **12/12**，每道题的答案排名均未改变。

这里的“Top-5”指正确原文能否进入默认送给模型的前五段。三道诊断题从 1/3 提高到 3/3，是这次已验证的改善；它们没有全部排第一，也没有证明千问对所有问题都能答对。

实验里尝试过直接给所有标题额外加分，但原开发集 Top-1 降到了 8/18，因此没有采用。仅删除“如何/怎么”也没有解决这组问题。保留的方案是在这些已知问题上比较后选出的，需要继续用同学独立编写的新问题检查泛化效果。

## 怎么验证这轮改动

现有诊断命令保持不变。在 `apps/api` 目录运行：

```powershell
& ..\..\.venv\Scripts\python.exe -m app.evaluation --dataset ..\..\evals\agent_insight --cases ..\..\evals\agent_insight\diagnostic_cases.json
```

应得到 B01 RANK 2、B02 RANK 4、B03 RANK 1。该命令在临时数据库重新导入公开资料，不修改你的演示库，不需要 API Key，也不产生模型费用。

自动测试还模拟了“网页答案接口 → 检索 → 模型”的流程，确认模型收到的前五段中包含实验入口说明，且收到的仍是用户原问题。模拟响应只证明接线正确；这轮没有重新调用真实千问，不能把它当作真实回答验收。

### 后续真实网页验收（2026-11-10）

用户重启后端后，在网页发送“Agent Insight 如何管理实验”，并提供了实际界面输出：显示“千问生成的回答”，内容涉及实验列表、实验设计、状态进度和 Case 操作；可展开 4 条 `experiments.md` 引用，标签为 S1、S2、S3、S5，其中 S2 是第 10–18 行的实验入口说明。这证明该问题在本次真实使用中已从资料不足转为带来源的回答；没有依据这一题计算总体回答准确率。

逐项对照原文后发现一个仍待修复的问题：S3 从第 280 行的“ace 的实验……”开始，完整原句其实是“选择已有 Trace 的实验保留当前 Trace，只重试失败评估。”（第 280 行）。当前切块的重叠起点 `end - overlap_chars` 可以落在单词和句子中间，模型因此把被截断的“ace”沿用到了答案。该题的检索与接线验收已通过，但表述质量还有缺陷。下一轮应优先处理切块边界/上下文完整性，并复核出处位置和原评测结果。

界面还直接显示了 `**` 等 Markdown 标记；目前答案用 React 普通文本展示，这是后续 B 岗可完善的显示问题。本次验收记录没有修改切块策略或前端渲染。

本轮整套后端测试为 **81 passed、1 skipped**，其中包括原评测、诊断题、其他主题的通用问法、原文位置及知识库/版本隔离检查。

## 当前仍需注意什么

原开发集还有一道有答案题没进入前五；无答案题也仍会搜到词面相近的原文，所以不能用检索分数代替证据判断。新规则只覆盖有限的通用问法。后面需要用更多独立问题复测，再从网页核对千问答案和引用是否由原文支持。

B 岗不需要改接口字段。CLI、`/questions` 和 `/answers` 共用这套检索函数；若电脑上还运行着旧后端进程，需要重新启动后端后才能使用新排序。详细实验选择见 [决策 0007](../decisions/0007-query-phrases-and-document-titles.md)。
