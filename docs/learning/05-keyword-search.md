# 第 5 课：先让问题找到资料，再谈大模型回答

上一步把文档切成带行号的块。这一步增加一个**本地命令行检索实验**：输入问题，返回最可能相关的原文块。它不会调用大模型、不会自动生成回答，也不会把“搜到了”解释成“答案一定对”。

## 自己试一遍

先按第 2 课把示例资料导入某个知识库，在 `apps/api` 目录运行：

```powershell
& ..\..\.venv\Scripts\python.exe -m app.cli search --kb 你的kb编号 --query "自动回答问题"
& ..\..\.venv\Scripts\python.exe -m app.cli search --kb 你的kb编号 --query "完全不存在的术语"
```

第一条应列出命中的文件、当前版本、原文行号、排序分数和最多 120 字的片段；第二条没有匹配时只显示 `No matching source chunks found.`。分数**只是同一次查询内的排序依据，不是正确率或可信度百分比**。

## 怎么找

1. `knowledge_store.py` 先从 SQLite 取出**指定知识库**中每篇文档的**当前版本**分块。旧版本和其他知识库不会进入候选集合。
2. `retrieval.py` 对中文使用相邻双字组合，例如“登录失败”变为“登录、录失、失败”；英文和错误码转成小写。查询和文档使用同一套规则。
3. 用一个小规模 BM25 排序基线打分：较少见的词通常更有区分力；同一词重复出现有收益递减；很长的块会做长度修正。标题路径也参与匹配，使长章节后面的块仍能通过标题被找到。
4. 只返回分数大于 0 的前几块；没有词命中就返回空结果，不编造“可能的答案”。

这套实现每次查询都会把当前块读进内存计算，适合课程早期的小资料集，不适合大量文档或公开服务。参数和中文双字切词只是起点，要用真实测试问题比较质量；它还没有同义词、向量检索、重排、权限系统或答案引用校验。

## 用测试约束“不会串资料”

自动化测试覆盖：中文与英文/错误码匹配、不同知识库隔离、只用当前版本、无证据返回空、非法输入拒绝。这些是功能正确性的底线，不等于已经证明检索质量优秀。后面应准备一小组人工标注的“问题→应命中文档/段落”，观察 Top-1/Top-5，再决定是否加入向量检索和模型 API。

原理参考：[Robertson 与 Zaragoza 的 BM25 综述](https://www.staff.city.ac.uk/~sbrp622/papers/foundations_bm25_review.pdf)。实现参考：[rank_bm25 项目](https://github.com/dorianbrown/rank_bm25)；它也强调分词与预处理需要应用自己负责。我们当前为了便于学习和控制行为，使用了小型纯 Python 实现，并没有安装该库。
