# 第 11 课：上传成功、可以检索、能回答，是三件事

更新于 2026-11-10。本轮 A 岗做了一个接口修正，并把上次网页联调中的失败问题保存为独立诊断样例。没有修改检索排序或模型选择，没有发起真实付费模型请求。

## 这次为什么改 `searchable`

原来的接口把它固定写成 `false`。后来导入逻辑已经会保存文本块，网页也接通了检索与千问，但这个旧字段一直没更新；B 岗据此做状态标签就会把可检索的文档显示成不可用。

现在文档列表根据数据库里是否存在“当前版本 + 当前切块策略”的文本块返回状态；成功上传的响应也带上导入后的状态。历史版本的块不会让当前版本误报就绪。同一份文件重复上传仍返回 `unchanged` 和原版本号；缺少当前块的旧资料会在重传时补齐块。

给页面的含义如下：

- `status: created/updated/unchanged`：文件成功存储、更新或保持原版本。
- `searchable: true`：当前版本有文本块，可以参与原文检索。
- `answer_status: generated`：这一次具体问题获得了模型回答；答案是否真的由原文支持，还要核对。

一个文件“可检索”，仍可能不包含某道题的答案，也不代表后端已经配置模型密钥。失败上传中的 `searchable: false` 只描述本次尝试：若是更新失败，旧文件可能仍然可检索，页面应刷新文档列表后显示真实状态。空文件和仅含空白的文件仍被拒绝。

## 从代码里怎样走一遍

`api_routes.py` 接收文件 → `knowledge_store.import_document()` 解析、版本判断、保存块 → 返回本次导入的 `searchable` → 页面展示结果。刷新列表时，`list_document_records()` 在数据库查询中用 `EXISTS` 检查当前版本的块。

`EXISTS` 可以理解为只问“符合条件的数据有没有至少一条”，不需要把所有原文加载出来。因此列表状态和检索使用相同的版本、知识库和切块策略边界。

测试覆盖了真实“上传 → 检索新版本”的流程，也覆盖了只有历史块、旧策略块、重复上传补块、坏编码和空白文件更新失败后的原版本保留。本轮完整后端检查为 **75 passed、1 skipped**；没有调用模型付费接口。

## 上次宽泛问题为什么没有答案

问题是“Agent Insight 如何管理实验？”。在固定的公开资料上重新检索，前五条为：

1. `view-traces.md` 第 515–519 行：如何关联原 Trace。
2. `datasets.md` 第 21–29 行：管理员准备 Benchmark 数据集。
3. `datasets.md` 第 29–43 行：准备数据集的脚本和启动流程。
4. `datasets.md` 第 57–70 行：Benchmark 的相关配置。
5. `view-traces.md` 第 356–365 行：事件落盘和后台处理。

正确的实验入口说明实际在 `experiments.md` 第 10–18 行，却不在前五。由此能确认**当前检索没有把所需入口说明送进候选证据**。这与上次网页返回资料不足的现象一致；当时模型原始响应没有保存，所以不能据此断言已完全解释那一次拒答。

移除产品名、只问“如何管理实验？”仍找不到该入口说明；改问“实验列表和创建实验”则把正确原文排在第 1。现有关键词排序容易受通用问法和产品词干扰，而更明确的主题词能帮助检索。这个对照只是诊断，不能要求使用者今后都改成固定问法，也不能靠把已知题改写后答对来宣称质量提高。

## 怎样无费用复查

新增的 [diagnostic_cases.json](../../evals/agent_insight/diagnostic_cases.json) 单独保存上述三种问法，不改变原来 `cases.json` 的 18 道有答案题和 5 道无答案题。原来的评测仍可照常跑；诊断题也不是独立留出集。

在 `apps/api` 目录执行这一条命令：

```powershell
& ..\..\.venv\Scripts\python.exe -m app.evaluation --dataset ..\..\evals\agent_insight --cases ..\..\evals\agent_insight\diagnostic_cases.json
```

程序会在临时数据库重新导入固定公开资料，与个人演示库无关；不需要密钥、不请求千问，也不改变已有数据库。当前结果：B01 MISS、B02 MISS、B03 RANK 1；三道诊断题 Top-1/Top-5 都为 1/3。原有评测测试仍通过（18 题答案块 Top-1 至少 12、Top-5 至少 17）。

下一轮检索优化应同时对比原开发集与这组诊断题，并由 B 岗补充没参与调参的新问题。只有在排序变化和回答依据都核对后，才能判断是否改善；不以降低拒答要求来掩盖漏检。

## 给 B 岗的对接说明

字段名、端点和请求格式没有改变。成功导入后可展示“已导入，可检索”；失败显示原因并刷新文档列表。不要把 `searchable` 当作“这道题能答对”的承诺。正式字段说明见 [知识库接口约定](../api/knowledge-base-v1.md)。
