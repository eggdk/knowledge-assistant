# 第 8 课：为什么两种本地切词一起用

上一步在真实 Agent Insight 原文上量到：18 道有答案题，只有 9 道把答案原文排在第 1。你选择先改进本地检索，所以这一课只动**找资料的排序**，不接模型 API、不生成回答。

## 先理解两个“找词视角”

旧方法把连续中文切成相邻两个字。例如“登录失败”变为“登录、录失、失败”。优点是不依赖词典，新产品名也能部分匹配；缺点是“录失”这种跨词片段没有独立意思。

新增方法用本地 `jieba` 的搜索模式切词。同一句会得到“登录、失败”这样较完整的词，更容易抓住用户真正关心的概念。[jieba 的项目说明](https://github.com/fxsjy/jieba)解释了搜索模式会在长词基础上补充短词。我们把版本固定为 `0.42.1`，每位同学安装项目依赖时都会得到同一版本；运行检索时不需要网络。

在 [`retrieval.py`](../../apps/api/app/retrieval.py) 里，每个文本块分别建立两份临时词频表，两份都使用同一套 BM25 风格公式打分，最后把分数相加后排序。检索命中仍返回原文块、文件名、当前版本和行号。**切词只影响排名，不修改数据库中的原文。**

```text
问题、当前版本原文块
      ├─ 相邻双字 → BM25 分数 A ─┐
      └─ jieba 词语 → BM25 分数 B ─┴─ A+B → 排名前五个原文块
```

## 和旧版对比

| 固定的 Agent Insight 开发集 | 旧版双字 | 新版两路相加 |
| --- | ---: | ---: |
| 答案块 Top-1 | 9/18 | 12/18 |
| 答案块 Top-5 | 17/18 | 17/18 |
| 无答案题真正无命中 | 0/5 | 0/5 |

演示集的 Top-1/Top-5 仍是 10/12、12/12。T06（子 Agent 导出）、D05（Benchmark 普通用户权限）、E02（监听实验）从非首位来到首位；E01（实验四步向导）从第 2 移到第 3，D02 仍未进入前五。因此这是一项**小规模开发集上的排序改进**，不是“已经学会理解问题”。

实验中还分别试过仅清理 Markdown/HTML 页面标记、仅用 `jieba` 取代双字切分；两种单独做法都只得到 8/18 的 Top-1，所以没有保留。以后要用 B 岗独立整理的新问题做留出验证，避免仅对我们已经看过的题调参。

## 自己验证

在仓库 `apps/api` 目录执行：

```powershell
& ..\..\.venv\Scripts\python.exe -m pip install -r requirements.txt
& ..\..\.venv\Scripts\python.exe -m app.evaluation --dataset ..\..\evals\agent_insight
& ..\..\.venv\Scripts\python.exe -m pytest
```

读代码时先看 `tokenize()` 和 `_search_words()`，再看 `_bm25_scores()`，最后看 `search_knowledge_base()` 怎样把两路分数相加。先理解“同一个问题用两种方式找词”即可，不需要先背 BM25 公式。

还要记住：5 道无答案题都搜出了词面相似的材料，分数仍不能表示答案有依据。`searchable: false` 和没有问答接口的状态保持不变；后面需要单独完成证据支持检查、引用校验和无法回答时的处理。
