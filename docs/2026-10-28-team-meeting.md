# 10 月 28 日两人会议：把下一阶段开发真正对齐

供 A 岗（后端）和 B 岗（页面与文件管理）在今晚直接照着讨论、勾选和记录。建议用 **75～90 分钟**，每项只要先定能支撑下一步的方案，不要求今晚把所有实现细节想完。

开会前，两人先看 [项目全貌图](learning/00-project-architecture.md)。当前仓库已有 MD/TXT 导入、原件与版本保存、文本切块、本地命令行检索和评测；尚无正式前端、问答生成、可点击引用及 Agent Insight 实际集成。B 岗本地代码与文件管理计划的**实际完成情况**需要本人现场展示，不能按计划文档推断。

## 会前各带三样东西（不用额外做 PPT）

- **A 带：** 当前仓库、`/docs` 的建库/上传演示、现有 [HTTP 接口约定](api/knowledge-base-v1.md)。说明目前网页上传返回 `searchable: false`，命令行检索能找片段，但还不能生成问答。
- **B 带：** 文件管理计划的最新版、已经写出的页面或代码所在位置、自己能运行到哪一步和卡点。若还只有计划，也如实说明。
- **两人都带：** 可投入的时间、课程交付/答辩日期、是否有可使用的大模型 API 额度或本地模型条件。日期与预算不清楚，会让功能优先级排错。

## 今晚优先拍板的 8 件事

每项会后至少写下：**选定方案、负责人、下次能看到的运行结果**。`[待填]` 留给你们开会时填写。

### 1. 最终演示要让老师看到哪条完整路径？（10 分钟）

**要问：** 老师现场能否从「建库 → 导入资料 → 打开 Agent Insight → 提问 → 看到有依据的回答或拒答 → 点开引用 → 反馈」走通？提交日期是哪天？老师是否另给了 Agent Insight 指定仓库或运行环境？

**方案：**

- A. 先把所有文档格式和管理按钮做齐，再开始问答与插件。
- B. 先做一条 MD/TXT 的完整问答与嵌入链路，再逐步补 Word/Excel/PDF、完整管理和反馈。

**建议选 B。** 课程的核心档位看重可信回答与插件集成；如果最后才接问答和平台，可能出现「资料管理很完整，但课题主体无法演示」。这只是**开发顺序**，不是删掉课程要求的格式和管理功能。

**会议记录：** 提交日期 `[待填]`；现场演示步骤 `[待填]`；老师指定仓库/环境 `[待填]`。

### 2. B 岗到底已完成什么、两人在哪里交接？（10 分钟）

**要问：** 文件管理计划里哪些已写成代码、哪些只是目录建议？代码在当前仓库的哪个分支？能否运行？B 希望 A 最先提供哪一个新接口？

**方案：**

- A. B 先把已写代码和截图/运行步骤放进 `knowledge-assistant` 的个人分支，双方从同一仓库继续。
- B. B 继续独立保存到本机，等页面完成后一次性合并。

**建议选 A。** 先合并一个最小可运行页面，能尽早发现接口字段、端口、跨域和依赖冲突。若暂时还没写页面，先提交页面骨架或明确的任务单即可，不要把计划文字说成已实现。

**会议记录：** B 的代码/计划位置 `[待填]`；已能运行的功能 `[待填]`；当前阻塞 `[待填]`。

### 3. 第一版管理页面究竟做哪些按钮？（10 分钟）

**要问：** 第一张页面先帮助管理员完成什么？文件夹上传是否必须在第一版做？上传部分成功时如何提示？

**方案：**

- A. 第一版只做「列知识库、建库、选一个或多个 MD/TXT、上传、显示每个文件结果、刷新文档列表」。
- B. 第一版同时做目录树、拖拽、预览、删除、编辑、索引进度和多格式。

**建议选 A。** 这些操作已有对应后端接口，可以快速完成真实联调。B 方案里的功能仍需做，但后端还没有删除、预览等接口，过早画按钮会形成只有外观的页面。当前接口对部分失败也返回 HTTP 200，页面必须逐个看 `files[].status` 和 `failed`，不能只根据状态码显示「全部成功」。

**会议记录：** 第一版页面功能 `[待填]`；文件夹上传的阶段 `[待填]`；每文件失败的显示方式 `[待填]`。

### 4. 前后端接口和本地联调怎么约定？（10 分钟）

**要问：** B 是否接受现有 `POST/GET /api/knowledge-bases`、文档列表和上传接口？需要改哪些字段？两个开发服务器分别用什么端口？

**建议：** 先保留现有 v1 接口，B 用一份真实 `intro.md` 完成创建、上传、重复上传、查看列表四步，再列出确实缺少的字段。单文件路径默认用文件名；选目录时才传对应的 `relative_paths`。前端如用独立开发服务器，优先配置开发代理转发 `/api` 到 FastAPI；确定前端地址后再决定是否需要限制范围的 CORS。

**还要明确下一批接口的顺序：** 搜索候选片段、读取引用原文、问答、反馈、删除/编辑。不要让 B 根据尚不存在的端点先写死页面。

**会议记录：** 前端本地地址 `[待填]`；API 需要调整的字段 `[待填]`；A 下一个接口 `[待填]`；B 对应页面动作 `[待填]`。

### 5. 悬浮插件怎样兼顾「任意网站可嵌入」和 Agent Insight 实际集成？（10 分钟）

**要问：** 最终交付物是可嵌入的小组件，还是只在 Agent Insight 里加一个页面？选用哪个具体 Agent Insight 仓库和版本？谁负责把它跑起来？

**方案：**

- A. 只写 Agent Insight 内部组件：接入平台较直接，但还需证明「任意网站可嵌入」。
- B. 只写独立演示网页：能展示外观，但课程要求的实际平台集成仍未满足。
- C. 做一个可独立挂载的悬浮组件，再在 Agent Insight 页面加一个很薄的接入层，同时在简单测试页证明可复用。

**建议选 C。** 一份组件覆盖两项验收。公开 Agent Insight 仓库当前说明其技术栈为 Next.js App Router + TypeScript，因此 B 应先看其实际布局和页面入口，再决定组件的打包与挂载方式；**不要仅凭这个信息立刻重写现有代码**。参考：[Agent Insight 的仓库说明](https://github.com/openeuler-mirror/agent-insight/blob/master/AGENTS.md)、[前端开发指南](https://github.com/openeuler-mirror/agent-insight/blob/master/docs/developer-guide/06-frontend.md)。

**会议记录：** 目标仓库及固定提交/分支 `[待填]`；独立测试页 `[待填]`；平台接入负责人 `[待填]`。

### 6. 问答用什么模型、证据不足时怎么办？（10 分钟）

**要问：** 是否有可用且允许课程项目使用的 API Key？预算上限？资料能否发给外部模型？若无模型可用，是否有能跑的本地模型机器？

**方案：**

- A. 后端接一个外部模型 API：通常更容易做出流式回答，但有费用和资料出境/服务可用性问题。
- B. 本地运行模型：资料留在本机，但安装、硬件、速度和效果风险更高。

**建议：** 先定「模型只由 A 岗后端调用，密钥不进网页和 GitHub；回答只能引用检索出的原文；证据不足就拒答」这一接口边界。具体供应商在确认预算和可用性后再定。先给 B 一个稳定的模拟回答接口结构用于页面联调，随后替换成真实模型；模拟结果**不能当作课程问答验收**。

**会议记录：** 可用模型与预算 `[待填]`；资料外发约束 `[待填]`；第一家供应方/本地方案 `[待填]`；无证据时界面文案 `[待填]`。

### 7. 怎么证明「找得到、答得对、不会乱答」？（10 分钟）

**要问：** 谁准备独立验收问题？怎样区分开发时调过的题和最终测的题？引用点开后显示哪些信息？

**现状：** 本地 Agent Insight 文档开发集的答案块 Top-1 为 12/18、Top-5 为 17/18；5 道无答案题都找到了表面相似的片段。这是**检索评测**，不是问答准确率。

**建议：** B 根据真实页面使用方式另写一小组此前未用于调参的问题，至少覆盖「资料明确有答案」「换种说法问」「资料没写」「资料更新后再问」四类；A 保存来源标注并跑检索，双方共同检查回答与引用是否真的由原文支持。问题、预期来源、实际输出、通过/失败原因都记录下来。没有答案的题不能只按检索分数判断。

**会议记录：** 独立题负责人 `[待填]`；首批题数与四类比例 `[待填]`；引用详情最少展示的信息 `[待填]`。

### 8. 课程其他要求按什么顺序补、每周如何合并？（10 分钟）

**要问：** Word、Excel、PDF 的解析谁负责、何时做？删除/修改和问答对录入谁负责？每周什么时候联调？谁审查合并？

**建议的顺序：** 先完成一条 MD/TXT 的可验证问答与嵌入路径；随后补文档删除/查看详情、问答对录入、Word/PDF/Excel、反馈与未答记录、体验完善。具体顺序应按剩余时间和老师验收风险调整；**五种格式和增删改查仍在最终清单里**。每项任务使用个人分支，提交能运行的最小改动，另一人至少做一次运行或代码复核；不要提交数据库文件、原始私人资料或 API Key。

**下周可交付目标（建议，今晚再确认）：** B 的首版管理页能调用现有建库/上传/列表接口；A 提供供页面使用的检索接口与引用片段读取方案；两人共同确定插件挂载位置，并留下一个实际运行的端到端演示记录。若时间不足，优先保留能跑通、能验收的路径。

**会议记录：** 本周 A 的一个可验收结果 `[待填]`；本周 B 的一个可验收结果 `[待填]`；共同联调时间 `[待填]`；负责整合与演示的人 `[待填]`。
