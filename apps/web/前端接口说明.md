# 前端接口与后端对接说明

本文说明前端对宿主页面提供的接入方式、文件管理模块的调用约定，以及前端使用的既有后端接口。当前版本没有新增后端 HTTP 服务或修改后端接口契约。

## 一、前端提供的页面与静态资源

| 入口 | 参数 | 行为 |
|---|---|---|
| `files.html` | 可选 `kbId` | 独立桌面文件管理页；读取真实知识库，优先选择参数对应的知识库，不存在时选择第一个；空列表显示创建入口 |
| `index.html` | 可选 `kbId` | 普通网页问答演示；把知识库 ID 传给插件，并在管理页链接中保留该 ID |
| `embed.js` | 脚本属性 `data-kb-id` | 在宿主网页右下角挂载悬浮入口和 iframe；根据脚本 URL 定位同目录 `widget.html` |
| `widget.html` | `kbId`、`hostOrigin` | iframe 内部聊天页面；两个参数通常由加载脚本生成，不需要宿主手工拼接 |

文件管理页与问答演示页之间跳转会保留 `kbId`。知识库和文件的持久化来自后端，不依赖浏览器保存演示记录。不同环境的真实 ID 不同，不应将个人本机 ID 固定写入共享代码。

构建后需完整保留 `embed.js`、HTML 页面与 `assets/`。加载脚本是普通脚本，依赖 `document.currentScript`，不能改成 `type="module"`。支持 HTTP(S) 和子路径，不支持直接双击 `file://` 页面。

## 二、宿主接入配置

```html
<script
  src="https://example.com/knowledge-assistant/embed.js"
  data-kb-id="kb_your_knowledge_base"
  defer
></script>
```

| 配置 | 说明 |
|---|---|
| `src` | 加载脚本的 HTTP(S) 地址；插件 HTML 和构建资源需保持相对目录关系 |
| `data-kb-id` | 要查询的一个知识库 ID，首尾空格会去除；未配置时可以打开界面，但发送按钮不可用 |
| `hostOrigin` | 由脚本从宿主页 origin 自动生成，用于校验宿主与 iframe 的消息来源 |

没有提供 `apiBaseUrl`、模型密钥或其他后端凭证配置。iframe 向自己的 origin 发起相对 `/api/...` 请求；开发和预览由 Vite 转发，实际静态部署应在插件资源所在 origin 配置同源转发。模型密钥只由后端管理，不能放入脚本属性或 URL。

重复加载时，脚本根据固定容器 ID `knowledge-assistant-embed` 避免重复挂载。容器使用开放 Shadow DOM，聊天内容放在 iframe 中，减少宿主样式冲突。

## 三、宿主与 iframe 消息接口

展开/收起使用同一种 `postMessage` 数据结构：

```ts
type WidgetStateMessage = {
  type: 'knowledge-assistant:state'
  open: boolean
}
```

- iframe 向宿主发送状态；加载脚本据此更新容器尺寸与 `data-open` 属性。
- 宿主可向对应 iframe 发送同格式消息控制展开或收起；脚本在 iframe 加载后先发送 `open: false`。
- 宿主脚本校验 `event.origin === widgetOrigin`、`event.source === frame.contentWindow`；iframe 校验来源为配置的宿主 origin 和 `window.parent`。
- 双方均要求 `type` 完全匹配且 `open` 为布尔值。此消息只负责界面状态，不承担问题、回答或文件传输。

需要由宿主主动展开时，可在 iframe 加载完成后调用：

```js
const container = document.getElementById('knowledge-assistant-embed')
const frame = container?.shadowRoot?.querySelector('iframe')
if (frame?.contentWindow) {
  frame.contentWindow.postMessage(
    { type: 'knowledge-assistant:state', open: true },
    new URL(frame.src).origin,
  )
}
```

### 卸载事件

单页应用离开相关页面或布局时，在插件容器上派发事件：

```js
document
  .getElementById('knowledge-assistant-embed')
  ?.dispatchEvent(new Event('knowledge-assistant:dispose'))
```

事件移除插件容器及宿主页的消息监听。事件处理只执行一次；重新挂载需重新加载脚本。前端没有额外提供全局 `window` 控制对象。

## 四、文件管理模块的前端调用接口

`src/features/file-management/api.ts` 导出以下函数，供本前端工程的组件使用；它们不是新增的 HTTP 路由，也不挂载为浏览器全局 API。

| 函数 | 返回值 | 用途 |
|---|---|---|
| `listBases(signal?: AbortSignal)` | `Promise<KnowledgeBase[]>` | 读取知识库列表；支持取消过期读取 |
| `createBase(name: string)` | `Promise<KnowledgeBase>` | 创建真实知识库，返回后端生成的 ID 和名称 |
| `listDocuments(kbId: string, signal?: AbortSignal)` | `Promise<FileRecord[]>` | 获取当前知识库文档并映射为前端视图模型 |
| `uploadDocuments(kbId: string, candidates: ImportCandidate[])` | `Promise<ImportResult[]>` | 提交原始文件与相对路径，解析逐文件处理结果 |

请求失败或响应结构不符合约定时抛出 `ApiError`，包含提示信息和可获得的 HTTP 状态码。请求等待上限为 60 秒；写入不会自动重试。超时不保证服务端没有写入，应先刷新列表核对结果。

主要前端数据类型定义在 `types.ts`：

| 类型 | 关键字段 |
|---|---|
| `KnowledgeBase` | `id`、`name`，来自后端 |
| `FileRecord` | `id`、`kbId`、`path`、`type`、`size`、`importedAt`、`searchable`、`versionNo`、`sha256` |
| `ImportCandidate` | `id`、`path`、`size`、`selected`、原始 `file: File` |
| `ImportResult` | `path`、`status`、`reason`，可带 `versionNo` 和 `searchable` |

`FileRecord.size` 当前为 `null`，因为文档接口未返回大小；页面显示“—”。未知扩展名映射为 `type: null`，不冒充其他文件类型。`ImportResult` 的 `skipped` 仅用于前端标记未提交项，后端导入状态仍只有下一节的四种。

## 五、前端调用的现有后端 HTTP 接口

基路径为 `/api/knowledge-bases`。文件管理不需要模型 API Key。

| 功能 | 方法与地址 | 请求 | 成功响应 |
|---|---|---|---|
| 知识库列表 | `GET /api/knowledge-bases` | 无 | `200`，`[{id,name}]` |
| 创建知识库 | `POST /api/knowledge-bases` | JSON `{name}` | `201`，`{id,name}` |
| 文档列表 | `GET /api/knowledge-bases/{kb_id}/documents` | 无 | `200`，文档数组 |
| 导入或更新 | `POST /api/knowledge-bases/{kb_id}/documents/import` | multipart，见下文 | `200`，`{files,failed}`，可能部分失败 |

创建名称在前端去除首尾空格，要求 1–100 个字符，并检查当前列表中的同名项。最终校验和 ID 生成仍由后端负责。

文档列表的每项字段：

```ts
type DocumentResponse = {
  id: string
  relative_path: string
  version_no: number
  sha256: string
  imported_at: string
  searchable: boolean
}
```

前端将路径、时间和版本字段映射为 `path`、`importedAt`、`versionNo`，详情直接使用该列表的元信息，没有调用不存在的单文件详情接口。

### 上传字段与返回结果

- `files`：重复字段，每项为原始 `File` 内容。
- `relative_paths`：与 `files` 数量、顺序一一对应；本前端对每项提交 `file.webkitRelativePath || file.name`。
- 路径须安全、唯一，并以该文件的实际文件名结尾；不能只提交磁盘路径代替文件内容。
- 使用 `FormData` 时不手工设置 `Content-Type`，由浏览器生成 multipart boundary。

```json
{
  "files": [
    {
      "relative_path": "manual/intro.md",
      "status": "created",
      "version_no": 1,
      "error": null,
      "searchable": true
    },
    {
      "relative_path": "broken.txt",
      "status": "failed",
      "version_no": null,
      "error": "Cannot decode broken.txt as UTF-8; check its encoding",
      "searchable": false
    }
  ],
  "failed": 1
}
```

| 状态 | 前端展示与处理 |
|---|---|
| `created` | 新增成功，重新读取列表 |
| `updated` | 更新成功，使用新版本与实际检索状态 |
| `unchanged` | 内容未变化，保留已有版本 |
| `failed` | 展示本次失败原因，不新增虚假文件；旧文件实际状态以重新读取的列表为准 |

不能仅凭 HTTP 200 判定整批成功。前端检查每个文件的状态和 `failed` 数量，并验证返回路径与所提交文件对应。

`searchable: true` 表示当前版本已有当前策略的文本块、可以参与检索；不保证模型已配置或回答正确。失败尝试的 `searchable: false` 不应覆盖旧版本的可检索状态。

### 现有问答插件使用的接口

| 接口 | 请求与处理 |
|---|---|
| `POST /api/knowledge-bases/{kb_id}/answers` | JSON `{question}`；展示 `answer`、`answer_status` 和 `citations` |
| `POST /api/knowledge-bases/{kb_id}/questions` | 仅在回答接口返回 503 时，由插件发送同一问题；展示 `matches` 中的原文，标注“尚未生成答案” |

上述两个接口为已有问答链路，本次未修改其服务端行为。问题按前端现有规则去空格并限制为最多 1000 个字符；当前没有多轮会话、流式输出或反馈接口接入。

### 异常与能力边界

| 情况 | 前端行为 |
|---|---|
| 未知知识库 `404` | 提示刷新知识库列表 |
| 请求格式/路径错误 `422` | 提示请求被拒绝，不显示写入成功 |
| 上传过大 `413` | 提示减少数量或大小；单文件超限也可能由后端以逐文件失败返回 |
| 服务/代理 `500`、`502`、`503`、`504` | 管理页提示后端不可用并允许重试，不回退演示数据 |
| 网络中断或超时 | 提示先刷新列表核对，避免重复写入 |
| 导入已完成但列表刷新失败 | 保留逐文件结果，单独提示刷新失败 |

当前可真实导入 UTF-8 的 MD/TXT（接受 BOM），每批最多 20 个、单文件最多 5 MiB，空白和坏编码文件由后端拒绝。前端能识别 DOCX/PDF/XLS/XLSX 标签，但真实导入会明确拒绝，等待后端解析能力。
